# 2026-05-28 更新：主效应改为城市×技术领域 DDD

## 新主问题

```text
IDC 服务覆盖是否降低算力依赖型技术领域的专利进入门槛？
```

相较上一版“IDC 服务覆盖扩大城市专利系统进入边界”，这一版更窄，但识别更强。

## 新主效应

主回归从城市年层面改为城市×技术领域×年份 DDD：

```text
Y_cft = beta ln(1 + IDC_scope_stock_{c,t-1}) × HighCompute_f
      + city × year FE
      + city × HighCompute FE
      + HighCompute × year FE
      + error_cft
```

等价差分形式：

```text
Y_high,ct - Y_low,ct
= beta ln(1 + IDC_scope_stock_{c,t-1})
 + city FE
 + year FE
 + error_ct
```

识别含义：

```text
同一个城市同一年，高算力依赖技术领域的新进入是否相对低算力领域更多。
```

这样可以吸收城市当年所有共同冲击，避免城市对城市比较太粗。

## 写作口径

主结论应写：

```text
IDC 服务覆盖增强后，同一城市同一年中，算力依赖型技术领域的新进入申请人、
新进入专利数和新进入份额相对低算力领域显著上升。
```

城市年主效应保留为背景：

```text
城市整体新进入边界也呈正向响应，但最硬识别来自技术领域 DDD。
```

不要写：

```text
IDC 只影响高算力领域。
```

更准确是：

```text
IDC 服务覆盖与城市专利进入扩容相关，并且这种进入扩容在算力依赖型技术领域额外更强。
```

## 论文结构调整

建议主文顺序：

1. 背景事实：城市年层面新进入申请人增加。
2. 主识别：城市×技术领域 DDD。
3. 机制：算力服务降低数据处理、算法验证、软件部署、数字原型开发成本。
4. 质量与身份清洗：授权、家族被引、剔除个人、剔除 one-shot。
5. 政策混淆防守：政策×HighCompute、事件 DDD、替换 HighCompute 定义。
