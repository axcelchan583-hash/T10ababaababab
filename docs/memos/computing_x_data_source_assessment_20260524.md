### 1.1 分地区大数据发展指数表

表名：`DE_RegionDevIndex.csv`

字段：

- 省份代码、省份名称；
- 城市代码、城市名称；
- 年份；

判断：

```text

```

原因：

- 它是“大数据发展指数”，不是算力基础设施；
- 城市覆盖太少，无法支撑全城市面板；
- 年份只到 2020，无法覆盖东数西算、智算中心和 2021 后算力扩张；
- 可作为控制变量、异质性变量或背景变量，但不能作为核心解释变量。

## 2. 别人怎么构造“算力基础设施”

### 2.1 IDC 许可证路线

最接近本项目的英文近邻是 Jiang (2025, Finance Research Letters)：

- X：Internet Data Center operating licenses；
- 来源：中国工信部发放的 IDC 经营许可证；
- 样本：2017-2022 年 A 股上市公司；
- Y：企业数字技术专利。

Jiang 的做法说明 IDC 许可证已经可以作为“computing infrastructure deployment”的论文级 X，但他的 Y 是企业数字创新，不是城市内部申请人结构。

中国工业经济近邻是许诺、毛聚、毛新述、王彦超《算力部署、数据跨域流动与企业全要素生产率——来自智算中心的证据》：

- 根据公开信息，该文从工信部政务服务平台 / 电信业务市场综合管理信息系统获取 IDC 许可证；
- 匹配企业统一社会信用代码；
- 根据许可证号识别发证年份；
- 根据业务种类筛选 B11 / 互联网数据中心业务；
- 根据许可证覆盖范围识别实际运营机房所在城市。

这个路线是目前最值得跟的。

### 2.2 国家绿色数据中心路线

有中文文章把绿色数字基础设施定义为国家绿色数据中心试点或建设城市：

```text
若城市 i 在 t 年份被纳入国家绿色数据中心试点或建设范畴，则 GDC_it = 1。
```

这类 X 的优点是官方、清楚、事件型强；缺点是偏“绿色数据中心”，不是一般算力供给，处理组也较粗。

### 2.3 数据中心相关企业数量路线

有文章用企查查按经营范围关键词匹配：

- 数据中心；
- 大数据；
- IDC 服务等。

然后按城市-年份归总企业数量。

这可以作为替代 X，但比 IDC 许可证弱，因为经营范围不等于真实运营，也不一定有机房。

### 2.4 省域综合指数路线

有文章构造省域算力基础设施建设水平指数，维度包括：

- 算力设施规模：数据中心数量、数据中心机架数量、企业持有 IDC 许可证数量；
- 网络运载能力：光缆线路长度、固定宽带下载速率、4G 基站数量；
- 算力支撑环境：信息传输/软件业就业、政府工作报告算力词频、信息服务业固定资产投资；
- 算力绿色发展：年平均气温、国家绿色数据中心数量、平均 PUE、能源电价。

这适合省级研究或作为城市研究的省级控制/背景，不适合作为城市内创新主体结构的主 X。

## 3. 我们当前 51miit 数据的状态

本地已有：

- `data/external_proxy/idc_proxy_51miit_license_details.csv`
- `data/processed/idc_proxy_city_year_2000_2024.csv`

明细表规模：

- 字段包括公司、许可证号、发证年份、业务种类、IDC 覆盖范围、注册地址；
- 当前 `idc_scope` 非空只有约 9.3%；
- 但检查后发现脚本漏抓旧式写法，如“因特网数据中心业务:北京市”，修正后可把覆盖范围非空数从 306 条提高到 356 条。

关键问题：

```text
我们现在的城市 X 混合了“覆盖范围城市”和“注册地址/公司名推断城市”。
```

因此它能做 smoke test，但正式稿必须降调为：

```text
IDC 经营许可代理变量
```

不能直接称为：

```text
真实本地算力容量 / 机柜 / MW / EFLOPS
```

## 4. 接下来应该怎么做

优先级最高的不是国泰安，而是把 IDC 许可证数据做完整。

### 4.1 完整重爬工信部 / 51miit

目标字段：

- 公司名称；
- 许可证号；
- 发证年份；
- 业务种类；
- 是否包含 B11 / 互联网数据中心业务；
- IDC 覆盖范围；
- 注册地址；
- 数据来源 URL；
- 是否为跨地区许可证；
- 是否为省内许可证。

城市归属规则：

1. 优先使用 `互联网/因特网数据中心业务：城市列表`；
2. 如果覆盖范围是省份，暂不直接展开到全省城市，优先记录为省级覆盖；
3. 覆盖范围为空时，注册地址只能作为 fallback，并在变量中单独标记；
4. 主回归优先用“覆盖范围可识别城市”的 X；
5. fallback 注册地 X 只作稳健性。

### 4.2 做三套 X，而不是只做一套

建议：

```text
X1 = IDC_scope_city_stock
只用许可证覆盖范围中明确出现的城市。

X2 = IDC_registered_city_stock
用注册地址/公司名推断城市。

X3 = IDC_combined_stock
覆盖范围优先，缺失时用注册地址 fallback。
```

判断标准：

- 如果 X1 和 X3 方向一致，可信度上升；
- 如果只有 X3 有结果，说明可能是注册地噪声；
- 如果 X1 样本太小，但 X2 和绿色数据中心/东数西算能互相印证，可以保守继续。

### 4.3 补官方事件型 X

至少补：

- 国家绿色数据中心名单；
- 国家算力枢纽和数据中心集群；
- 国家超算中心城市；
- 智算中心公开名单。

这些不一定当主 X，但可以验证“IDC 许可证城市是否真的是算力设施城市”。

## 5. 当前 verdict

```text
国泰安这两包不能救主 X。
别人做“算力基础设施”最接近的是 IDC 许可证路线。
我们已经有一个可用但偏粗的 51miit 代理数据；
下一步应该完整重爬/重清洗 IDC 许可证，优先提取覆盖范围城市，而不是转向全国智能算力规模或大数据发展指数。
```

如果要继续这个选题，主 X 暂定为：

```text
城市 IDC 经营许可覆盖强度
```

而不是：

```text
城市真实算力容量
```

除非后面能补到机柜数、MW 或 EFLOPS。
