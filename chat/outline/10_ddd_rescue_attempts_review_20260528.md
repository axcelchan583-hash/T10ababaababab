# 给网页版评审：DDD 救法全部试跑后的判断

请评估：这些结果是否意味着城市×技术领域 DDD 应该放弃作为主识别。

## 背景

原 DDD 的 `ln1p` OLS 为正：

```text
新进入申请人数：0.2184***
新进入专利数：0.2560***
```

但 count-level PPML 为负：

```text
新进入申请人数：-0.1544***
新进入专利数：-0.1270**
```

因此继续试了三条救法：

1. PPML + `offset(log(total_patents_field))`
2. PPML + `offset(log(active_applicants_field))`
3. 份额/进入率/是否有新进入者的 DDD

## 1. PPML + 总专利 exposure

全样本、未加政策交互：

| HighCompute 定义 | 新进入申请人数 | 新进入专利数 |
|---|---:|---:|
| broad | 0.0270 | 0.0381 |
| no_h04 | -0.0019 | 0.0045 |
| G06/G16/G10L | 0.0186 | 0.0169 |
| G06 only | 0.0113 | 0.0098 |

加入政策 × HighCompute：

| HighCompute 定义 | 新进入申请人数 | 新进入专利数 |
|---|---:|---:|
| broad | 0.0796** | 0.0195 |
| no_h04 | 0.0858* | 0.0271 |
| G06/G16/G10L | 0.1064** | 0.0340 |
| G06 only | 0.0994* | 0.0284 |

解释：申请人数 rate 在加政策交互后有弱正结果，但新进入专利数不显著。

## 2. PPML + 活跃申请人 exposure

broad、全样本：

| Y | 不加政策 | 加政策×HighCompute |
|---|---:|---:|
| 新进入申请人数 | -0.0296*** | -0.0199 |
| 新进入专利数 | -0.0346 | -0.0976* |
| 技术领域首次进入申请人数 | -0.0457*** | -0.0439*** |
| 技术领域首次进入专利数 | -0.0557 | -0.1069** |

解释：给定活跃申请人规模后，高算力领域新进入率没有上升。

## 3. 份额/进入率

全样本、未加政策交互：

| HighCompute 定义 | 新进入申请人率 | 新进入专利份额 |
|---|---:|---:|
| broad | 0.0108 | 0.0308** |
| no_h04 | 0.0109 | 0.0128 |
| G06/G16/G10L | 0.0258 | 0.0207 |
| G06 only | 0.0262 | 0.0190 |

剔除个人和 one-shot 后，broad 的新进入专利份额也消失：

| 样本 | 新进入申请人率 | 新进入专利份额 |
|---|---:|---:|
| all | 0.0108 | 0.0308** |
| no individual | 0.0020 | 0.0148 |
| no one-shot | 0.0036 | 0.0190 |
| no individual and no one-shot | -0.0051 | 0.0081 |

## 4. 是否有新进入者

全样本 LPM：

| HighCompute 定义 | 是否有新进入申请人 |
|---|---:|
| broad | -0.1329*** |
| no_h04 | -0.1585*** |
| G06/G16/G10L | -0.1547*** |
| G06 only | -0.1500*** |

解释：真正 extensive margin 是负的。

## 当前内部判断

DDD 救不回来。更准确的说法是：

```text
ln1p OLS 的正结果不具备足够稳健性；
PPML、rate、share、any-entry 都没有形成一致正证据。
```

如果论文继续做，应该回到城市年进入边界结果，或者重新找更细粒度且能通过 PPML/rate 检验的新 Y。

## 请评审

1. 这是否已经构成 DDD 主识别的 No-Go？
2. `PPML + total exposure + policy` 中申请人数的弱正结果是否还有利用价值？
3. “是否有新进入者”为负，是否直接推翻“高算力领域进入门槛下降”机制？
4. 如果回到城市年主线，是否还值得继续冲中文较好期刊？
5. 还有没有比 city×field×year 更合适的细粒度设计？
