# Claude 网页版评审回复保存稿：算力基础设施与城市创新主体结构

日期：2026-05-24

说明：本文件保存 Claude 网页版对 T10 选题的评审意见要点。原回复为英文长评审报告，核心判断和建议如下。

## 1. 一句话结论

**Pivot-and-continue，条件式 Go。**

Claude 认为，“城市算力基础设施 -> 城市内部专利申请人集中度”这个问题，在中国城市和全量 CNIPA 申请人数据场景下，AJG 3+ 近邻文献中尚未被直接占掉。

但前提是必须完成三个转向：

1. 不再写“数字基础设施促进创新总量”；
2. 不再写“上市公司创新优势被削弱”；
3. 以“进入扩容 + 头部再集中”的双机制为主线。

核心说法：

```text
Entry expansion and head re-concentration coexist.
```

也就是：

```text
算力基础设施降低创新进入成本，同时放大头部主体的吸收能力优势。
```

## 2. 最危险近邻

最危险近邻是 Forman, Goldfarb & Greenstein 关于信息技术与发明活动分布的文献。

Claude 建议明确区分：

| 维度 | 近邻文献 | 本项目 |
|---|---|---|
| X | 美国商业互联网扩散 | 中国城市算力 / IDC / 东数西算 / 智算中心 |
| Y | 地区之间专利地理分布 | 城市内部申请人 HHI、Top5/Top10、新进入申请人 |
| 数据 | USPTO 专利 | CNIPA 全量申请人数据 |
| 机制 | 地区追赶、远距离协作 | 进入成本下降 + 吸收能力互补 |

第二类近邻是中国数字基础设施 / 宽带中国促进城市或企业创新总量的文献。Claude 认为这类已经很拥挤，不能作为本文贡献。

第三类近邻是 DeStefano, Kneller & Timmis 关于云计算和企业增长的文章。Claude 认为这是“友军文献”，可以支撑云 / 算力降低进入成本和异质性吸收的理论逻辑。

## 3. 文献边界

Claude 将文献分成三类：

1. 数字 / 网络 / 算力基础设施 -> 城市或企业创新总量：非常拥挤；
2. IT / AI / 数字创新的企业或地理集中趋势：英文高水平文献很多；
3. 城市基础设施冲击 -> 城市内部申请人 HHI / Top share / 新进入申请人：在中国城市场景下基本空缺。

因此，边际贡献只能写成：

```text
从创新总量效应转向城市内部创新主体分布效应。
```

## 4. 推荐题目

英文推荐：

```text
Computing Infrastructure and the Within-City Concentration of Innovation:
Entry Expansion and Head Re-concentration in Chinese Patent Applicants, 1985-2025
```

中文推荐：

```text
算力基础设施与城市内创新主体结构：
基于1985-2025年中国专利全样本的证据
```

或：

```text
东数西算、算力枢纽与创新主体集中度：
“入场扩张”与“头部强化”的并存
```

## 5. 理论框架

建议使用：

1. 通用目的技术 GPT：算力基础设施作为现代 GPT；
2. 吸收能力：已有知识、组织能力和研发能力决定谁能吸收算力红利；
3. 实验成本下降：云 / 算力降低进入和试错成本；
4. 创新再集中 / declining business dynamism：头部主体可能进一步集中创新。

避免：

1. 泛泛的集聚经济；
2. 纯粹熊彼特式创造性破坏；
3. 中文数字经济论文常见的“数字基础设施促进创新”套话。

## 6. 机制检验建议

Claude 建议只保留 2 个主机制和 1 个辅助机制。

### 主机制 A：进入成本下降

结果应体现在：

- 新进入申请人增加；
- 新进入申请人份额提高；
- 低吸收能力城市或低门槛技术领域更容易出现进入扩容。

### 主机制 B：吸收能力互补

结果应体现在：

- Top5 / Top10 份额提高；
- 高基期吸收能力城市中头部集中更强；
- 处理前 Top5 / Top10 申请人增长更快并持续留在榜单。

### 辅助机制：人才流动

如果能识别发明人跨城市流动，可以作为短机制；否则不必强行做。

Claude 明确不建议把产业结构、金融发展、财政科技支出等都叫机制。

## 7. 异质性建议

最重要的三个：

1. 专利类型：发明专利 vs 实用新型 vs 外观；
2. 技术领域：数字 / AI / 云 / 数据处理 vs 非数字；
3. 城市基期吸收能力：高 AC 城市应更容易头部再集中，低 AC 城市应更容易进入扩容。

可放附录：

- 东部 vs 西部，用于政策相关性。

不建议主做：

- 单纯人口规模；
- 沿海 vs 内陆；
- 高新区 vs 非高新区；
- SOE vs 非 SOE，除非主体识别非常稳。

## 8. 识别升级顺序

Claude 建议的最小升级顺序：

1. 城市 FE + 年份 FE；
2. 城市线性趋势；
3. 省份 × 年份 FE；
4. 基期能力 × 年份 FE；
5. 剔除超大城市和省会；
6. 控制其他数字政策：宽带中国、智慧城市、大数据试验区、高新区、创新型城市等；
7. 多期滞后；
8. 事件研究，至少 4 个政策前窗口；
9. 稳健 staggered DID：Callaway-Sant'Anna、Sun-Abraham、de Chaisemartin-D'Haultfoeuille；
10. 替代 X：机柜数、MW、FLOPS、智算中心、东数西算等。

Claude 认为不需要一开始就做 IV；如果准实验和稳健性充分，AJG 3 可以不靠 IV。

## 9. 数据工程优先级

Claude 认为 AJG 3+ 必须优先做：

1. 申请人名称清洗和集团合并，尤其是 Top 申请人；
2. Top5 / Top10 申请人身份分类；
3. A 股上市公司及子公司 / 集团匹配；
4. 高价值 / 数字 / AI / 云专利分类；
5. 从公开年份切换为申请年份；
6. 补真实算力强度：机房地址、机柜数、MW、FLOPS、智算中心等。

## 10. Go / Pivot / No-Go 标准

Claude 给出四个硬标准：

1. 机制可分离：低吸收能力城市进入扩容更强，高吸收能力城市头部集中更强；
2. 预趋势干净；
3. 剔除超大城市后仍成立；
4. 控制其他数字政策后仍成立。

决策：

- 4/4 成立：Go；
- 3/4 成立：Pivot；
- 2/4 成立：重大修改；
- 小于等于 1/4：No-Go。

## 11. 最重要提醒

Claude 认为当前题有价值，但不能停在现有 TWFE 和 IDC 许可证变量。最关键下一步是：

```text
申请人清洗 + Top 主体识别 + 申请年份 + 强 FE / 事件研究 + 替代 X。
```
